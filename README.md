# 小学试卷自动推送

每天北京时间 10:00 自动检索四家公开站点，以邮件推送从未推送过、近三年内、适配当前小学年级和学期的试卷。没有新增资源时不发邮件。

## 自动化流程

GitHub Actions 自动安装 Python 和 Chromium → 执行回归测试 → 抓取并筛选 → 比较发送历史 → 发送 HTML 邮件 → 发信成功后原子保存历史 → 提交历史到默认分支。工作流串行运行，避免定时任务和手动任务同时发出同一批邮件。

包含四个来源：

| 来源 | 抓取方式 | 筛选边界 |
|---|---|---|
| 小学试卷网 `appsj.szxuexiao.com` | 公开首页、苏教分类、当前年级目录 | 语文统编、数学苏教；按资源标题明确年份筛选 |
| 牛津中小学英语网 `njzxxyy.com` | 公开目录及 Discuz 搜索表单 | 英语译林一起点，排除三起点 |
| 二一教育 `21cnjy.com` | Chromium 使用公开搜索与“免费”筛选 | 必须有免费标识、标题年份、正确教材版本和试卷类型；收费资源不推送 |
| 小学试卷网 `xxsj.org` | 当前年级学科目录、当期上下册目录和江苏地区目录 | 原教材版本匹配，或标题明确属于江苏；年份、年级、学期不放宽 |

小学入学基准为 2026 年 9 月，每年 9 月自动升一级，7、8 月仍使用上一学年的年级。版本固定为语文统编、数学苏教、英语译林一起点、道德与法治统编、科学苏教、音乐与美术苏少。音乐、美术分别查询，统编/部编作为同一版本的公开名称处理。一、二年级英语可接受译林版对应年级名称；更高年级必须明确一起点，不能用三起点替代。

四站资源标题还必须明确匹配当前年级和学期：9月至次年1月为上学期，2月至8月为下学期，使用上海时区。不根据每年校历自动调整开学日。支持“上册/上学期/上半学期/第一学期”和对应下学期名称；未标学期、上下册合集或其他年级资源跳过。例如2026年11月只选一年级上学期，2027年2月选一年级下学期，2027年9月选二年级上学期。搜索仍使用版本、年级、学科宽查询，再按每条标题精确过滤，以免只搜索“上学期”遗漏“上册”资源。已发送历史保留，不因规则修改重复发送。

四站统一只按资源标题（页面展示的试卷文件名）中的明确年份判断，不读取网页发布时间、上传时间或最后回复日期作为筛选依据。如“2025”或“2025-2026学年”，跨年取起始年，并以该年1月1日作为保守筛选下界（不是发布日期），必须落在近三年窗口内。比如2026年11月扫描时，2023年标题因不能确认月份而跳过，2024年及以后可纳入。无年份、不连续学年、多组歧义年份、未来年份跳过；即使网页刚刚上传，也不能让过期标题通过。邮件明确标注“标题年份，非发布日期”。不下载附件来读取隐藏文件名。

仅 `xxsj.org` 允许江苏地区作为教材版本的替代依据：标题写明“江苏”、江苏13个地级市（带“市/地区”后缀）、可明确归属江苏的县级市/县/区名称可通过。鼓楼区、海州区等跨省同名地名单独出现时不能确定江苏，需同时有省市信息；不从栏目侧栏或下载链接推断资源地区。教材匹配资源不强制江苏地区。新站最多访问24个公开分类页，每个学期/江苏学科列表最多前2页，不回填全站历史；不访问网盘、不扫码、不转存附件，邮件只提供原站详情链接。

## 一次性安全配置

仓库代码不包含任何真实发件邮箱、收件邮箱或 SMTP 授权码。以下信息全部来自环境变量或 Actions Secrets：

| Secret | 用途 |
|---|---|
| `EMAIL_FROM` | 发件用的 126 邮箱地址 |
| `EMAIL_TO` | 收件邮箱 |
| `EMAIL_SMTP_PWD` | 发件邮箱的 SMTP 授权码，不是邮箱登录密码 |

在仓库 `Settings → Secrets and variables → Actions` 配置。也可在已登录 GitHub CLI 的本机终端安全输入（不要把授权码写在命令参数或聊天中）：

```powershell
gh secret set EMAIL_SMTP_PWD --repo OWNER/paper-auto-send
```

配置齐全后，将仓库 Actions **Variable** `DELIVERY_ENABLED` 设置为 `true`。未启用时定时任务只做无发信扫描，不会尝试缺凭据的 SMTP 请求。配置邮件凭据后，首次以非 dry-run 手动执行验证真实送达；以后无需电脑开机或每天操作。

SMTP 使用 `smtp.126.com:465`，保持 TLS 验证。授权码只能由邮箱所有者在邮箱服务中取得；本项目不会自动改变邮箱密码或安全设置。

保存或更换授权码后，可以在 Actions 手动运行 **Verify SMTP connection**（`smtp-check.yml`）。它只验证 TLS 连接和 SMTP 登录，不发送邮件、不扫描站点、不修改发送历史；成功不代表收件箱已收到邮件，真实投递仍需有合格新增资源。

## 定时与手动执行

`.github/workflows/run.yml` 使用 UTC `0 2 * * *`，即北京时间 10:00，并提供手动触发输入 `dry_run`（默认开启）。

- `dry_run=true`：真实访问全部站点，但绝不连接 SMTP、不改发送历史，生成不含邮箱/试卷正文的 `run-summary.json`。
- `dry_run=false` 且 `DELIVERY_ENABLED=true`：正常推送，缺少任何必要凭据会明确失败。
- 手动输入 `source=primary` 只扫描原小学试卷网，`source=xxsj` 只扫描新站；默认及每日定时扫描全部四站。本地对应 `python main.py --source xxsj --dry-run`。
- 每次运行提供 30 天保留的 Actions artifact，含诊断统计和发送历史恢复副本。
- 仓库默认分支需要允许工作流使用 `contents: write` 写入 `sent_list.json`。推送失败不会伪装成成功；请先恢复 artifact 中的历史再重跑，防止重复发信。

Actions 定时可能延迟，不是准点 SLA；GitHub 也可能因仓库长期无活动、配额或服务状态暂停定时。自动化不会绕过 GitHub 的配额限制。发信与磁盘/Git 提交无法组成跨系统事务：SMTP 已接受但进程/历史持久化中断时，重跑存在重复风险，不能承诺“严格恰好一次”投递。

## 本地运行

推荐 Python 3.12（最低 3.10）：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m unittest discover -v
python main.py --dry-run --report run-summary.json
```

如果已有 Chrome 或 Edge，可设置 `$env:PLAYWRIGHT_CHANNEL = "chrome"` 或 `"msedge"`，而不下载 Chromium。浏览器下载因企业证书失败时，应正确配置操作系统/Node 的受信任证书，不能关闭 TLS 校验。

正常发送前，在当前进程环境安全注入上述三个变量后运行 `python main.py`。不要将真实凭据保存到源码、本地可提交配置或终端历史。`.env` 被忽略且不会自动加载，避免不经意地把本地密码带入运行。

## 诊断与维护

邮件采用“学科 → 试卷类型”两级分类：语文、数学、英语、道德与法治、科学、音乐、美术；多学科合集或无法明确学科的归入“综合／未明确学科”。各学科内再分为期中考试卷、期末考试卷、单元检测、随堂练习与阶段测评、专项训练、综合复习、其他试卷。顶部汇总学科数量，每个学科内显示类型数量、完整标题、来源、年份依据和原站详情链接。每份资源只归入一组，空分类不显示；“期末专项训练”“期中复习”等优先归入专项/复习，不冒充整套考试卷。分类仅根据标题，不代表已检查附件正文，不影响筛选和发送历史。

需要查看真实邮件排版时，可手动运行 Actions 的 **Send email layout preview**。它从 `xxsj.org` 获取符合当前规则的实际资源，允许包含已发送条目，发送一封主题标注“排版测试”的邮件，不修改正式历史；没有合格资源或扫描失败则明确失败且不发信。该工作流无定时触发，手动执行即会向已配置收件人发送测试邮件。

- 网站错误、无可识别结果页面、访问限制或验证码会明确记录诊断并使进程非零退出，不会称为“今日无新增”。其他来源已获取的合格资源仍可发信，成功后保存历史。
- 原始网站内容视为不可信输入：链接限定在四个来源域名，过滤非 HTTP(S)、用户信息及异常端口；邮件 HTML 转义标题和链接，资源链接移除搜索跟踪参数以稳定去重。
- 仅访问公开页面，不登录、不下载附件、不绕过访问控制、验证码或反爬，不执行网页任意表单。
- 请求至少间隔 2 秒；二一教育每关键词每日最多 3 页，达到边界会警告。此低频扫描并非全站历史归档，初次运行也不保证回填所有旧资源。
- 四站均按上述标题年份规则筛选，不伪造发布日期；无法确认年份的条目仍跳过。
- 网站选择器改版时需维护 `paper_auto_send/sources.py` 并补回归测试；外部网站不可用不能靠自动化保证消除。
- 云端与本地网络的访问结果可能不同。部署实测中牛津英语站对 GitHub 托管执行器返回 HTTP 403；程序会停止该站扫描，不更换身份、代理或尝试绕过。其余来源仍可产生邮件，但运行状态会保留失败提示，因此目前不能保证云端四站全部可用。

## 测试

`python -m unittest discover -v` 覆盖学年/日期边界、真实卡片形态、免费筛选、版本和试卷类型、搜索失败判定、HTML 安全、稳定去重、dry-run、不发信场景以及邮件成功/失败与历史更新顺序。测试 SMTP 为 mock，不产生真实投递。
