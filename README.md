# 小学试卷自动推送

每天北京时间 8:00 计划触发检索四家公开站点，发送一封“每日试卷更新与完整清单”：包含已保存且仍符合当前规则的全部资源，并列明今天新增哪些。**没有新增也发送邮件**；清单为空时发送状态通知。近三年标题年份、当前年级和学期、江苏地区或对应学科教材版本等筛选条件不变。8:00是计划触发时间，不是保证送达时间。

## 自动化流程

GitHub Actions 自动安装 Python 和 Chromium → 执行回归测试 → 抓取四站 → 合并历史资源库并按当前规则重新筛选 → 比较已通知历史 → 发送完整清单和新增明细 → 发信成功后更新已通知历史 → 将资源库和通知历史提交到默认分支。工作流串行运行，避免并发写入状态。

`resource_catalog.json` 保存资源完整标题、链接、来源和年份依据；`sent_list.json` 记录哪些资源已通过 SMTP 成功通知过。“今日新增”指首次成功通知的新资源（不等于今天发布），邮件顶部列新增标题和链接，正文标记“今日新增／历史保留”。已推送资源每天仍会出现在清单中，但不会反复标成新增。资源库在发现后保存，通知记录只在 SMTP 接受后更新，因此发信失败后新增会留待重试。

每天都对历史资源重新核验：不再符合年级、学期、年份或教材/地区规则的不显示，但不从资源库删除，方便将来切换学期。某站当天失败时保留该站已存的合格资源，并明确标注扫描不完整；邮件保留历史条目不代表当天已重新验证下载链接。即使四站都失败，也尝试发送历史清单和故障状态，运行仍标失败以便诊断。

升级前旧状态只存 URL，没有完整标题。新资源库从升级后的真实扫描开始回填，无法从旧 URL 单独推断标题/教材或保证恢复所有旧条目；历史 URL 不清空，重新抓到且已通知过的资源不会误标新增。未再次抓到的旧资源不能编造后放入邮件。

包含四个来源：

| 来源 | 抓取方式 | 筛选边界 |
|---|---|---|
| 小学试卷网 `appsj.szxuexiao.com` | 公开首页、苏教分类、当前年级目录 | 语文统编、数学苏教；按资源标题明确年份筛选 |
| 牛津中小学英语网 `njzxxyy.com` | 公开目录及 Discuz 搜索表单 | 英语译林一起点，排除三起点 |
| 二一教育 `21cnjy.com` | Chromium 使用公开搜索与“免费”筛选 | 必须有免费标识、标题年份、江苏地区或对应学科教材版本、试卷类型；收费资源不推送 |
| 小学试卷网 `xxsj.org` | 当前年级学科目录、当期上下册目录和江苏地区目录 | 原教材版本匹配，或标题明确属于江苏；年份、年级、学期不放宽 |

小学入学基准为 2026 年 9 月，每年 9 月自动升一级，7、8 月仍使用上一学年的年级。版本固定为语文统编、数学苏教、英语译林一起点、道德与法治统编、科学苏教、音乐与美术苏少。音乐、美术分别查询，统编/部编作为同一版本的公开名称处理。一、二年级英语可接受译林版对应年级名称；更高年级必须明确一起点，不能用三起点替代。

四站资源标题还必须明确匹配当前年级和学期：9月至次年1月为上学期，2月至8月为下学期，使用上海时区。不根据每年校历自动调整开学日。支持“上册/上学期/上半学期/第一学期”和对应下学期名称；未标学期、上下册合集或其他年级资源跳过。例如2026年11月只选一年级上学期，2027年2月选一年级下学期，2027年9月选二年级上学期。搜索仍使用版本、年级、学科宽查询，再按每条标题精确过滤，以免只搜索“上学期”遗漏“上册”资源。已通知历史保留，旧资源继续展示但不会反复标成新增。

四站统一只按资源标题（页面展示的试卷文件名）中的明确年份判断，不读取网页发布时间、上传时间或最后回复日期作为筛选依据。如“2025”或“2025-2026学年”，跨年取起始年，并以该年1月1日作为保守筛选下界（不是发布日期），必须落在近三年窗口内。比如2026年11月扫描时，2023年标题因不能确认月份而跳过，2024年及以后可纳入。无年份、不连续学年、多组歧义年份、未来年份跳过；即使网页刚刚上传，也不能让过期标题通过。邮件明确标注“标题年份，非发布日期”。不下载附件来读取隐藏文件名。

四站统一要求标题明确满足“江苏地区或对应学科教材版本”至少一项：标题写明“江苏”、江苏13个地级市（带“市/地区”后缀）、可明确归属江苏的县级市/县/区名称可通过。鼓楼区、海州区等跨省同名地名单独出现时不能确定江苏，需同时有省市信息。非江苏资源必须在标题中明确写出对应学科版本：语文/道法统编或部编，数学/科学苏教，音乐/美术苏少，英语译林一起点（一、二年级可接受译林版）。人教版数学、苏教版语文等不属于该学科的目标版本，不能仅因标题有“版”就通过；多版本冲突或多学科不明确的非江苏标题跳过。

不从搜索词、栏目侧栏、邻近卡片或二一教育隐藏的 `version_name` 字段推断教材/地区。二一教育元数据仅用于核验免费价格和资源类型，不再替代标题证据。抓取和发送前各核验一次，每条邮件显示“入选依据”，保证能看出它按江苏地区还是具体教材版本入选。教材匹配资源不强制江苏地区，年份/当前年级学期仍须同时符合；此调整不清空历史、不自动补发旧邮件。

新站最多访问24个公开分类页，每个学期/江苏学科列表最多前2页，不回填全站历史；不访问网盘、不扫码、不转存附件，邮件只提供原站详情链接。

## 一次性安全配置

仓库代码不包含任何真实发件邮箱、收件邮箱或 SMTP 授权码。以下信息全部来自环境变量或 Actions Secrets：

| Secret | 用途 |
|---|---|
| `EMAIL_FROM` | 发件用的 126 邮箱地址 |
| `EMAIL_TO` | 收件邮箱 |
| `EMAIL_TO_ADDITIONAL` | 可选的新增收件邮箱，多个地址用英文逗号分隔；保留原 `EMAIL_TO`，不支持显示名 |
| `EMAIL_SMTP_PWD` | 发件邮箱的 SMTP 授权码，不是邮箱登录密码 |

在仓库 `Settings → Secrets and variables → Actions` 配置。也可在已登录 GitHub CLI 的本机终端安全输入（不要把授权码写在命令参数或聊天中）：

```powershell
gh secret set EMAIL_SMTP_PWD --repo OWNER/paper-auto-send
```

配置齐全后，将仓库 Actions **Variable** `DELIVERY_ENABLED` 设置为 `true`。未启用时定时任务只做无发信扫描，不会尝试缺凭据的 SMTP 请求。配置邮件凭据后，首次以非 dry-run 手动执行验证真实送达；以后无需电脑开机或每天操作。

SMTP 使用 `smtp.126.com:465`，保持 TLS 验证。授权码只能由邮箱所有者在邮箱服务中取得；本项目不会自动改变邮箱密码或安全设置。

每日任务和手动排版预览均向全部已配置收件人发送，地址重复时只发送一次，收件人可在 To 中互相看到地址。任一地址被 SMTP 拒收时明确报错且不更新通知历史；其他地址可能已收到，重试存在重复投递风险。

保存或更换授权码后，可以在 Actions 手动运行 **Verify SMTP connection**（`smtp-check.yml`）。它只验证 TLS 连接和 SMTP 登录，不发送邮件、不扫描站点、不修改发送历史；成功不代表收件箱已收到邮件，真实投递需运行每日任务。

## 定时与手动执行

`.github/workflows/run.yml` 使用 UTC `0 0 * * *`，即北京时间 8:00，并提供手动触发输入 `dry_run`（默认开启）。GitHub 排队和网站抓取均可能导致延迟，不能保证8:00收件。

- `dry_run=true`：真实访问站点并合并已存清单，但绝不连接 SMTP、不改资源库或通知历史，生成不含邮箱/试卷正文的 `run-summary.json`。
- `dry_run=false` 且 `DELIVERY_ENABLED=true`：正常推送，缺少任何必要凭据会明确失败。
- 手动输入 `source=primary` 只扫描原小学试卷网，`source=xxsj` 只扫描新站；默认及每日定时扫描全部四站。本地对应 `python main.py --source xxsj --dry-run`。
- 每次运行提供 30 天保留的 Actions artifact，含诊断统计、资源库及通知历史恢复副本。
- 仓库默认分支需要允许工作流使用 `contents: write` 写入 `sent_list.json` 和 `resource_catalog.json`。推送失败不会伪装成成功；请先恢复 artifact 中的状态再重跑，防止新增标记失真。

Actions 定时可能延迟，不是准点 SLA；GitHub 也可能因仓库长期无活动、配额或服务状态暂停定时。自动化不会绕过 GitHub 的配额限制。发信与磁盘/Git 提交无法组成跨系统事务：SMTP 已接受但进程/历史持久化中断时，重跑存在重复风险，不能承诺“严格恰好一次”投递。

## 本地运行

推荐 Python 3.12（最低 3.10）：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m unittest discover -v
python main.py --dry-run --report run-summary.json
```

如果已有 Chrome 或 Edge，可设置 `$env:PLAYWRIGHT_CHANNEL = "chrome"` 或 `"msedge"`，而不下载 Chromium。浏览器下载因企业证书失败时，应正确配置操作系统/Node 的受信任证书，不能关闭 TLS 校验。

正常发送前，在当前进程环境安全注入上述三个变量后运行 `python main.py`。不要将真实凭据保存到源码、本地可提交配置或终端历史。`.env` 被忽略且不会自动加载，避免不经意地把本地密码带入运行。

## 诊断与维护

### 后台监控与管理

使用仓库的 [GitHub Actions 管理页面](https://github.com/nuoke2007/paper-auto-send/actions)，目前没有独立后台或服务器：

- 选择“每日试卷更新与完整清单”，查看每次执行时间、各步骤日志，或通过 **Run workflow** 手动执行；测试扫描选择 `dry_run=true`，实际每日清单选择 `false`。
- 执行详情的 artifact 包含 `run-summary.json`、`resource_catalog.json`、`sent_list.json`。报告的 `delivered` 判断 SMTP 是否接受，`daily_resources`/`new_resources` 判断总数/新增，`failed_sources` 判断来源失败。任务标红不一定代表邮件失败。
- 工作流菜单可禁用/启用定时任务；仓库 Actions Variable `DELIVERY_ENABLED=false` 仅停止发送、保留定时扫描。Secrets 页面用于安全更新邮箱配置，不显示秘密值。
- 任务计划8:00触发，实际创建时间和开始时间在运行详情可见。GitHub托管定时不提供准点保证；单次排队延迟不能通过修改邮件代码消除。

邮件采用“学科 → 试卷类型”两级分类：语文、数学、英语、道德与法治、科学、音乐、美术；多学科合集或无法明确学科的归入“综合／未明确学科”。各学科内再分为期中考试卷、期末考试卷、单元检测、随堂练习与阶段测评、专项训练、综合复习、其他试卷。顶部汇总学科数量，每个学科内显示类型数量、完整标题、来源、年份依据和原站详情链接。每份资源只归入一组，空分类不显示；“期末专项训练”“期中复习”等优先归入专项/复习，不冒充整套考试卷。分类仅根据标题，不代表已检查附件正文，不影响筛选和发送历史。

邮件为紧凑双栏设计（最大960px），手机600px以下切换单栏；顶部学科目录可跳到指定学科，学科末尾可返回目录。完整标题本身就是资源链接，来源、年份和入选依据合并为小字，避免重复按钮占行。新增资源在每个分类内优先显示并高亮，顶部仅列新增学科数量，不重复整份标题清单。全部合格历史仍保留，不截断标题、不用脚本或默认隐藏内容；部分邮箱可能忽略媒体查询或内部锚点，仍可顺序阅读并访问全部资源。

需要查看真实邮件排版时，可手动运行 Actions 的 **Send email layout preview**。默认 `scope=all` 重新扫描四站，发送“今日四站试卷汇总”，邮件列出每站成功/失败状态和合格数量，允许包含已发送条目，不修改正式历史；部分来源失败时仍发送其他站结果，但运行非零退出以保留失败诊断。`scope=xxsj` 仅发送新站“排版测试”，该站扫描失败不发信。没有任何合格资源不发信。该工作流无定时触发，手动执行即会向已配置收件人发送邮件。

- 网站错误、无可识别结果页面、访问限制或验证码会明确记录诊断并使进程非零退出，不会称为“今日无新增”。其他来源已获取的合格资源仍可发信，成功后保存历史。
- 日志按站点分别显示合格数量、未发送数量和扫描是否完成；诊断报告的 `source_counts` 与 `new_source_counts` 区分“抓到了但已发过”和“本站抓取失败”。
- 原始网站内容视为不可信输入：链接限定在四个来源域名，过滤非 HTTP(S)、用户信息及异常端口；邮件 HTML 转义标题和链接，资源链接移除搜索跟踪参数以稳定去重。
- 仅访问公开页面，不登录、不下载附件、不绕过访问控制、验证码或反爬，不执行网页任意表单。
- 请求至少间隔 2 秒；二一教育每关键词每日最多 3 页，达到边界会警告。此低频扫描并非全站历史归档，初次运行也不保证回填所有旧资源。
- 四站均按上述标题年份规则筛选，不伪造发布日期；无法确认年份的条目仍跳过。
- 网站选择器改版时需维护 `paper_auto_send/sources.py` 并补回归测试；外部网站不可用不能靠自动化保证消除。
- 云端与本地网络的访问结果可能不同。部署实测中牛津英语站对 GitHub 托管执行器返回 HTTP 403；程序会停止该站扫描，不更换身份、代理或尝试绕过。其余来源仍可产生邮件，但运行状态会保留失败提示，因此目前不能保证云端四站全部可用。

## 测试

`python -m unittest discover -v` 覆盖学年/日期边界、真实卡片形态、免费筛选、版本和试卷类型、搜索失败判定、HTML 安全、稳定去重、dry-run、每日无新增仍发信、历史保留与重筛、全站失败仍发历史清单、空清单通知以及邮件成功/失败与历史更新顺序。测试 SMTP 为 mock，不产生真实投递。
